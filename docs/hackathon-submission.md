### Project Description

Macro Mixer is a generative-UI workbench for map / reduce research. Instead of producing one long chatbot answer, it turns a question into a live spatial board of model-generated cards that can expand, stream, be selected, and collapse into synthesis while preserving provenance.

The operator starts with a seed question, then runs **Expand** to fan it out through multiple Gemini-powered lenses such as base case, dissent, and wildcards. Each lens streams into its own card in parallel. The user can then select the strongest or most interesting cards and run **Reduce**, which synthesizes the selected material into a new card. The source cards are tucked behind the synthesis rather than deleted, so the interface keeps the reasoning graph inspectable.

The real-world problem is that AI research workflows often create too much output across too many tabs, chats, and documents. Macro Mixer gives users a visual way to compare perspectives, preserve source lineage, compress noise, and iterate toward a better answer. The UI is generated by the agentic process itself: Gemini streams become structured board nodes, card states, provenance links, provider lanes, and event logs rather than static text.

The project is working code built with Next.js App Router, React 19, TypeScript, Tailwind CSS 4, `@google/genai`, and `@ag-ui/core`. The server-side `/api/expand` route opens parallel Gemini streaming calls, multiplexes them over one SSE response, and emits AG-UI-style lifecycle, text, and state events. The `/api/reduce` route streams one synthesis call over the selected cards. On the client, React consumes the SSE frames, updates the board, records provenance fields (`parentIds`, `directive`, `lensId`, `provider`, `model`, and `status`), and renders the evolving work surface.

AG-UI is used as the event contract for run lifecycle, streaming text messages, custom events, snapshots, and state deltas. The board state is also A2UI-ready: cards, provider lanes, active-card projections, and provenance metadata are modeled so generated or declarative UI surfaces can inspect and re-render them cleanly. For this hackathon cut we kept the app lean and direct with Gemini as the model provider, while leaving the event/state architecture ready for CopilotKit, MCP Apps, or multi-provider extensions later.

## Required Vision / Objectives / Intent / Tech Stack Response

### 1. Project Vision

Macro Mixer is a generative-UI prototype for research workflows where the hardest part is no longer getting text from a model, but organizing, comparing, compressing, and trusting the output. The specific problem we are solving is the gap between linear chat and the way people actually think through complex questions: they ask for multiple angles, compare disagreements, choose useful fragments, synthesize them, and repeat.

Our prototype turns that process into a visual map / reduce interface. A user starts with one question or card, expands it into multiple streamed lens cards, selects the best or most relevant cards, and reduces them into a synthesis card. The synthesis keeps provenance, so users can inspect which cards contributed to it and what directive produced the run. The generated UI is the evolving work surface: cards bloom from a parent, stream in parallel, collapse into a synthesis, and remain traceable as an inference graph.

### 2. Objectives

Our main objective was to learn how to build agentic interfaces where model output controls more than a text transcript. We wanted to practice designing a structured event/state model for generative UI, mapping streaming inference to visible interface changes, and preserving provenance so AI output remains inspectable.

Technically, we focused on a working end-to-end loop: server-side Gemini streaming, SSE multiplexing, AG-UI-style lifecycle and text events, React board state, selection, synthesis, and persisted sessions. Product-wise, we wanted to learn how small visual operations like expand and reduce can make AI research feel more controllable than chat.

### 3. Statement of Intent

Our team is a strong fit for this hackathon because Macro Mixer sits directly at the intersection of agentic systems, interface design, and practical research workflows. We are not only asking a model to generate UI decoration; we are designing an interface where the agent's reasoning process produces durable, interactive objects that a human can select, inspect, and recombine.

We bring a builder-oriented perspective to the cohort: strong interest in AI workbenches, streaming interfaces, provenance, and the ergonomics of human judgment around model output. Our contribution to the hackathon community is a concrete pattern others can reuse: treat AI output as a graph of transformations, not as a transcript. Expand for diversity, reduce for synthesis, and keep lineage visible.

### 4. Tech Stack

Macro Mixer is built with Next.js App Router, React 19, TypeScript, Tailwind CSS 4, Google Gemini through `@google/genai`, Server-Sent Events, and AG-UI through `@ag-ui/core`.

The app has two server-side streaming operations. `POST /api/expand` runs multiple Gemini streams in parallel, one per lens, and multiplexes chunks back to the browser as SSE frames tagged by lens index. `POST /api/reduce` sends selected completed cards to Gemini and streams one synthesis response. The client parses the SSE frames, updates board state, renders streaming cards, tracks selection, collapses source cards behind synthesis cards, and records provenance metadata.

AG-UI provides the event vocabulary for run lifecycle, text streaming, custom events, and state deltas. The board state is intentionally projection-friendly for A2UI-style generated surfaces: cards, provider lanes, active-card detail, event logs, and provenance metadata are structured explicitly. We kept the hackathon MVP focused on direct Gemini calls for speed and reliability, while the event architecture leaves room to add CopilotKit or MCP Apps integrations without changing the core map / reduce interaction.
